> **产品约束（2026-11-05 用户澄清）**：测试中使用的 `HULIANWANG DIGUI` /「星网运营商」身份仅为**验收模拟**，**不要**为模拟账号、单一星座或「星网」品牌做专项增强、硬编码别名/芯片/批量逻辑。修复与增强一律做成**通用能力**（任意 NORAD/星座标签/系统池 TLE 装载/批量认领按标签），用通用回归用例验收即可。


> **产品约束（续 · 2026-11-05）**  
> 1. **AI 左侧栏**：暂作占位**保留**，本轮修复**不要删除**侧栏 AI 入口。  
> 2. **AOE**：系统池日更编目（两行根数）；筛查任务可将 AOE 选为主星源或副星编目。日更包含 **GP(TLE)+CDM+AOE**。  
> 3. **总览报告**：首页「总览」增加**报告选择与下载**（可选报告类型/时间窗等 → 下载），作为本轮产品补强。  
> 4. **态势交会选中 UX**：底栏文案「事件云」→「**交会事件**」；开启后显示黄/橙/红交会点；**跟踪/点选红点**时镜头放大，效果对齐旧项目交会选中——渲染**交会双方 3D 模型 + 双方轨道**；交会点外围**白圈**需**缓慢自转 + 呼吸缩放**。参考仓库 [`jeffreytanhao-eng/Opensapce-Safety-Platform`](https://github.com/jeffreytanhao-eng/Opensapce-Safety-Platform)（`BaseScene` 选中交会：`selectHeatPair` / 热力选中轨道组 + TCA 模型；近距离机位）。  
> 5. **总览「数据源」分段**：现网为 Stage 1 mock，**不驱动** KPI/关注事件。按用户决定：**从总览移除**，能力迁到**筛查页任务参数**——主星用 **TLE / 星历**，副星用 **编目 / CDM** 等（一单一源，受档位与凭证约束）。总览只保留「数据源健康」。  
> 6. **态势底栏**：去掉「**安全热力图**」按钮（用户附图）；底栏保留「交会事件」与「初始化窗口」等必要项。

> **产品约束（续 · 认领 / 档位 / 隔离 · 必须 API 强制，前端隐藏不够）**  
> 1. **业主认领（owner-claim）仅认证 VIP**：`plan=vip` 且 `status=active` 方可 `claimType=owner`；`free`/`normal` → 403。  
> 2. **授权范围**：VIP 仅可认领该组织**已授权**目标（通用：标签 / NORAD 白名单 / 合同范围；**禁止**星网/HULIANWANG 硬编码）。  
> 3. **唯一业主**：同一 NORAD 全局至多一个 `owner`；第二家 → 冲突拒绝（区分本组织已有 vs 他组织占用）。  
> 4. **关注（watch）不互斥**：多家可同时 watch；普通/免费仅 watch，受合理上限（`objects_max` 或独立 `watch_max`）。  
> 5. **普通账号全库可搜**：编目搜索/浏览走系统池 full（与托管列表解耦）；用量仍受筛查/托管配额。  
> 6. **客户隔离**：上传 CDM、筛查、复算、凭证、报告按 `org_id` 隔离；系统池数据显式分支。  
> 7. **超管改档副作用**：降到非 VIP 立即禁新 owner；超额禁止新增；审计 `before`/`after` 含 plan/status/limits 快照。Story 见 **R2-11（C0–C6）**。


## 0. 再开发目标

把现网从「能登录、能看系统池 CDM、能点红云」推进到：

1. **运营商作业链可跑通**：认领目标 → 系统池 TLE 可用 → 筛查产出事件 → 黄橙红云 → 详情深链。  
2. **安全与运维达标**：受保护 API 鉴权、审计落库、日更 **GP+CDM+AOE** + cron、健康字段一致。  
3. **产品对齐**：AI 侧栏占位保留；通用编目发现与批量认领（服从 R2-11）；总览报告下载；筛查主/副星源；态势交会选中放大 + R2-10；**认领闸门 / 唯一业主 / 全库搜索 / 客户隔离 / 超管改档副作用**。

**刻意不做（本轮）**：完整机动引擎（仍 P3）；计费；推倒 Cesium/Three；把竞赛 `server.jsc` 拷入；**删除 AI 侧栏**（暂留占位）。

## 2. R0 · 阻塞与安全（必须先做）

### R0-1 强制鉴权 `/cgi/events`（及同类泄露面）

| 项 | 内容 |
|---|---|
| **问题** | 匿名 `GET /cgi/events` 返回 200 全量系统池交会 |
| **做什么** | 所有 `/cgi/events*`、以及任何返回组织/系统池业务数据的列表/详情默认 `requireAuth`；复核 `catalog/*` 匿名策略（stats 可保留公开摘要，但不得泄露完整 CDM/事件） |
| **验收** | 无 Token → 401；组织 Token → 仅可见策略允许的数据；超管策略单独说明 |

### R0-2 筛查主星 TLE 装载（星网作业链核心）

| 项 | 内容 |
|---|---|
| **问题** | `GET /cgi/objects/:id` 已联表出 `tle_line1/2`，筛查仍报「缺少有效两行根数」；无 sync/bind API；`tleSource`/`primaryNorads` 被丢弃 |
| **做什么** | 1）筛查 worker **直接 join** 系统池最新 GP（与 objects 详情同源）；或 claim 时 **快照拷贝** TLE 到 object 行并在日更后可 `sync-tle`。<br>2）新增 `POST /cgi/objects/sync-tle`（org 范围批量）与/或筛查前自动 sync。<br>3）兼容 **alpha-5** NORAD（≥100000，TLE 行号如 `1 A1193U`）。<br>4）真正解析并尊重 `primaryNorads`（可选子集筛查，避免 231 颗一次打满队列）。 |
| **验收** | 对已托管的 `HULIANWANG DIGUI-01`（62323）发起筛查 → `n_primary≥1` → 状态 done（或明确 failed 原因非「缺根数」）；至少产出 0+ 事件且不僵死 |

### R0-3 筛查任务生命周期：取消 + 僵死恢复

| 项 | 内容 |
|---|---|
| **问题** | #3 长期 `running` 且 `n_primary=0`，堵住队列；`DELETE/cancel` 404 |
| **做什么** | `POST /cgi/screens/:id/cancel`；worker 心跳/超时（如 10min 无进度 → failed）；启动时回收 orphan running；管理/组织 UI 增加「取消」 |
| **验收** | 可取消 queued/running；超时自动 failed；新任务不再永久排队 |

### R0-4 清现网积压（运维一次性）

| 项 | 内容 |
|---|---|
| **做什么** | 部署 R0-2/3 后，超管或 SQL 将僵死 running 标 failed，清空无效 queued；再跑 1 次星网小子集筛查验收 |
| **注意** | 密钥与 DB 操作走服务器侧，**禁止**把口令写进仓库或聊天回显 |

## 3. R1 · 交会质量与数据运维

### R1-1 危险等级对齐黄 / 橙 / 红

| 项 | 内容 |
|---|---|
| **问题** | DB/API 仅 `red`/`low`；UI 混用「高危/警告/关注」 |
| **做什么** | 统一枚举：`red` / `orange` / `yellow`（或 `critical`/`observe`/`watch` **双向映射到色**）；列表筛选、态势云着色、弹窗文案一致；CDM 入站与筛查产出共用分级规则（Pc / miss / 官方 severity） |
| **验收** | 事件列表与态势云至少出现两种以上颜色；无事件时不画装饰彩云 |

### R1-2 重算官方 Pc 与 CDM 对齐

| 项 | 内容 |
|---|---|
| **问题** | `POST .../recompute` 的 `official.pc=0`，详情主 Pc 仍有 CDM 值 |
| **做什么** | official 行直接读取事件关联 CDM 的 Pc；无 CDM 时显示「无官方 Pc」而非 0；Foster/Chan/Alfano 保持独立 |
| **验收** | 对已知 CDM 事件重算，official 列与详情主 Pc 同量级 |

### R1-3 日更：GP+CDM + cron + 健康字段统一

| 项 | 内容 |
|---|---|
| **问题** | 仅 manual；`catalog/stats` 停在 10-28 sidecar 文案 |
| **做什么** | 1）确保 Space-Track GP/CDM 凭证可用。<br>2）启用 `DAILY_FETCH_CRON`（每日 1 次 GP+CDM），失败告警/退避。<br>3）`catalog/stats` 的 lastGp/Cdm **改为读** `daily_fetch` / `orbital_fetch_batches`，删除过期 sidecar 文案；AOE 字段显示日更状态。<br>4）超管 `/admin` 增加「日更状态 + 手动触发」（GP/CDM/AOE）。 |
| **验收** | health：GP/CDM 有 last_success；AOE 在已配置时有 last_success；cron batch 存在；stats 与 health 同日 |

### R1-4 总览 KPI 组织化

| 项 | 内容 |
|---|---|
| **做什么** | 24h/7d、今日筛查、关注事件默认 **本组织托管相关**；全局系统池指标单独标注「系统池」；去掉 Stage1 mock 文案 |

| **做什么** | 从态势 dock / 底栏移除「安全热力图」入口与相关未接线或竞赛遗留热力开关；清理无用 i18n。**保留**「交会事件」（原事件云）与「初始化窗口」。若代码内仍有旧 heat 图层，默认关闭且无 UI 入口即可，不必本轮大删算法。 |
| **验收** | 态势底栏不可见「安全热力图」；交会事件开关与初始化仍可用；交会选中放大（R2-7）回归通过。 |

### R2-10 交会放大态：模型上轨 + 蓝色同型 + 名称标签 + 黄橙云可见性

| 项 | 内容 |
|---|---|
| **来源** | 2026-11-05 Jeffrey 态势截图（红云选中 THOR ABLESTAR DEB 等）：白模离轨、无名称标签、观感几乎只有红云。 |
| **问题** | 1）`eventCloudThree.conjPairPositions` 把双方模型钉在云心两侧做视觉分离，轨道却按真 TCA 画 → **模型不在轨道上**。<br>2）`addModel` 经 `resolveCatalogModelKey`（`object_type: ''`）+ 共享白材质 → **白色扁平模**，未必匹配左栏类型（卫星/残骸/碎片/未知）。<br>3）交会放大态无名称标签（星历/左栏选中有准星名称）。<br>4）前端虽有黄/橙/红 `LEVEL_STYLE`，现网 7d 约 red=48 / orange=1 / yellow=3；黄橙半径更小且远时衰减，云体为单层 Sprite，效果弱于旧 `Opensapce-Safety-Platform`。 |

| **验收** | 选中任意交会云：双方蓝模在各自轨道上；型号与左栏同 NORAD 一致；右上有名称标签；仿真钟拨到已知橙/黄 TCA（如橙 CSS×HULIANWANG DIGUI-01；黄 TITAN×ARIANE DEB）时对应色云可见可点；红橙黄观感可区分。 |

### R2-11 认领权 / 唯一业主 / 档位权限 / 客户隔离 / 超管副作用

> 原独立R2-11已并入本条。2026-11-05 双账号 + 超管实测缺口如下；验收以 **API 强制**为准。

#### 现网缺口

| # | 现象 | 严重度 |
|---|---|---|
| G1 | `normal` 仍可 `claimType=owner` 成功 | **P0** |
| G2 | VIP 可对任意 NORAD（如 ISS）owner，无授权范围 | **P0** |
| G3 | 无全局「每 NORAD 唯一 owner」 | **P0** |
| G4 | normal=`managed`、free=`sample`，不能全库搜索 | **P0** |
| G5 | 筛查 CDM SQL 未按 org 隔离客户 CDM | **P0** |
| G6 | 降档不回收超额托管（仅拦新增） | **P1** |
| G7 | 审计列表 `before`/`after` 常不完整 | **P2** |
| G8 | 超管升降级/关停/配额覆盖链路可用 | 回归基线 |

验收夹具（非正式产品）：VIP `orgtest@test.local` orgId=5；普通 `normaltest@test.local` orgId=6；超管 `admin@openspace.local`。密码不入文档。

**建议实现顺序**：C0 → C2 → C1 → C3 → C4 → C5 → C6。

#### R2-11-C0 业主认领闸门（档位）

| 项 | 内容 |
|---|---|
| **问题** | normal/free 仍可 owner-claim（G1） |
| **做什么** | `POST /cgi/objects`（及批量）在 `claimType=owner` 时校验 `org.plan==='vip'` 且 `status=active`；否则 403「仅 VIP 组织可业主认领」。Watch 保持开放（受配额）。前端：普通账号禁用「业主认领」，仅保留关注。 |
| **验收** | normal/free：owner → 403；watch 配额内 → 200。VIP：授权内 owner → 200。 |

#### R2-11-C1 授权范围（通用，非星网专项）

| 项 | 内容 |
|---|---|
| **问题** | VIP 可对任意 NORAD owner（G2） |
| **做什么** | 1）表 `org_claim_scopes`（org_id, scope_type=`tag`\|`norad`\|`constellation_key`, scope_value…），超管可配。<br>2）owner-claim 校验目标在范围内；未配置范围的 VIP → **拒绝全部 owner**（安全默认）。<br>3）**禁止**硬编码 HULIANWANG/星网。 |
| **验收** | 超管授权标签 A 后仅 A 内可 owner；范围外 → 403；换标签回归同样通过。 |

#### R2-11-C2 唯一业主

| 项 | 内容 |
|---|---|
| **问题** | 缺全局唯一 owner（G3） |
| **做什么** | 对 `claim_type='owner'` 建 NORAD **部分唯一**（优先 DB）；并发第二家 → 冲突。Watch 多行允许。取消认领/超管释放后可再认。 |
| **验收** | orgA owner X 成功；orgB 再 owner X → 409/403「已被他组织业主认领」；orgB watch X 配额内可。 |

#### R2-11-C3 普通账号全库搜索

| 项 | 内容 |
|---|---|
| **问题** | normal/free 编目池看不到全库（G4） |
| **做什么** | **catalog search/browse** 与托管列表解耦：normal+vip → 系统池 **full**（分页限流）；free 默认亦可只读全库检索或保持 sample（产品默认：**normal 全库可搜**）。托管/筛查用量仍受 `objects_max`/`screen_day`。 |
| **验收** | normal 搜 STARLINK（或等价）命中量 ≫ 本组织 objects；objects 列表仍只有自己的托管。 |

#### R2-11-C4 客户数据隔离（CDM / 筛查 / 任务）

| 项 | 内容 |
|---|---|
| **问题** | 筛查副星 CDM 未 org 隔离（G5） |
| **做什么** | 客户上传 CDM、org 凭证缓存、筛查 job、复算 run、导出：一律 `WHERE org_id=?`。系统池 CDM 用 `source=system` 显式分支。 |
| **验收** | orgA 上传 CDM 后，orgB secondary=cdm **读不到** A；跨 org 直访 ID → 404/403。 |

#### R2-11-C5 超管改档副作用

| 项 | 内容 |
|---|---|
| **问题** | 降档不撤 owner 能力、不回收超额（G1+G6）；审计 before/after 弱（G7） |
| **做什么** | 1）`PATCH plan` 降到非 vip：**立即禁止新 owner-claim**；已有 owner 默认 **方案 A 保留只读**（`owner_frozen` / 前端只读，不可新增）；备选方案 B：批量 owner→watch 并截断到 `objects_max`（需产品确认）。<br>2）超额禁止新增；超管可「强制裁剪」或组织自助取消。<br>3）审计 `before_json`/`after_json` 含 plan/status/limits 快照。<br>4）关停：登录 403「组织已被暂停」保持。 |
| **验收** | vip→normal 后 owner→403；超额不可新增；改档审计可见 before/after；suspend 无法登录；升回 vip+授权后 owner 恢复。 |

#### R2-11-C6 超管控制台补强（叠在 R2-4 上）

| 项 | 内容 |
|---|---|
| **做什么** | 既有开通/改档/关停/配额 override 之外：① 编辑业主授权范围（C1）；② 查某 NORAD 当前 owner；③ 可选强制释放 owner；④ 审计页完整 before/after。 |
| **验收** | 超管：配范围 → VIP 认领成功 → 另一 VIP 冲突；改档/关停/配额与 C0/C5 一致。 |

### R2-5 其它已登录缺陷

| 项 | 内容 |
|---|---|
| 星历 NORAD 展示 | 名称后缀数字 ≠ NORAD 时，标签与信息面板用真实 `norad_id` |
| 态势黑地球 / 相对速度「—」 | 修纹理/光照或数据缺省提示；速度有值则显示 |

## 5. R3 · 提升建议（网络 / GitHub 新能力，可选接入）

> 下列为 **增强建议**，不挡 R0–R2 出门。接入时注意许可证与「非认证 CARA」免责。
>
> **商用计费边界（2026-11-05 用户澄清，必读）**  
> - 外部数据源（Space-Track、AOE、其它 SSA/编目 API）与重算/筛查算力均有**收费账号与限流**。  
> - **真商用时，平台不得用系统共享账号配额去补贴终端用户的拉取与筛查**；系统池仅作有限展示/样例或按合同计量的受控容量。  
> - 客户生产用量应走 **客户自备凭证**（设置页已规划）+ **档位计量/超额拒绝或按量计费**；系统账号日更只服务「平台编目基线」，不得被 org 接口无限透支。  
> - 任何 R3 引擎（OrbVeil/SatGuard/ASTRA…）接入时，必须带上：**每 org 配额、队列优先级、限流回压、费用归属（客户凭证 vs 系统池）** 的设计，禁止「平台默默代打全量编目」。

| # | 来源 | 建议接入点 | 价值 | 收费/限流注意 |
|---:|---|---|---|---|
| 1 | [OrbVeil](https://github.com/ncdrone/orbveil)（Apache-2.0） | 筛查 worker 旁路/对照：KD-tree + Foster/MC | 全编目筛查加速 | 算力按 org 配额；主星批大小受 `screen_day`；禁止系统池无限代筛 |
| 2 | [SatGuard](https://github.com/cesabici-bit/satguard)（MIT） | Foster/Chan/Alfano、CDM KVN、fleet、PDF | 算法与报告对齐计划书 | CelesTrak/Space-Track 拉取走**客户凭证或计量后的系统池**；PDF 导出计 `recompute`/`export` 配额 |
| 3 | [ASTRA](https://github.com/ISHANTARE/ASTRA)（MIT） | VIP：2D 积分 / 6D MC；OMM+STM | 高保真 Pc | MC 高耗时 → **仅 VIP + 严格 recompute_day**；可选客户自备 worker |
| 4 | [caspy](https://github.com/ut-astria/caspy)（GPL-3.0，注意传染） | OEM/ITC→CDM | 星历对星历筛查 | 进程外 sidecar；算力归属客户任务；先法律评估 |
| 5 | [CelesTrak](https://celestrak.org/) 公开星座分组 GP | 日更旁路或交叉校验 | 编目新鲜度 | 遵守其 ToS/限流；**不可**当作无限免费给所有商用客户代拉的主通道 |
| 6 | 通用星座元数据（自有标签表 / 公开编目） | 态势层与资产聚合 | 任意组织可复用 | 元数据可平台维护；**轨道根数拉取仍计费/限流** |
| 7 | Space Safety Docs 作业流 | 对齐认领→轨迹→筛查→分级→报告 | 产品叙事 | 文档层无外部费用 |

**落地原则**：系统账号 = 平台基线（有上限的日更）；客户账号 = 自费自限流；UI 必须暴露「当前走 system_pool 还是 org_credential」与剩余配额。

**编目新鲜度**：系统池相对 Space-Track/CelesTrak 的滞后应在总览「数据源健康」显示；测试曾用 HULIANWANG 仅作模拟，不作为产品专项。
