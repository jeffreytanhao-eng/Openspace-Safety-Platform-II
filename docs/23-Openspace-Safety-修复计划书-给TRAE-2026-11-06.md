## 0. 结论摘要（先读）

### 0.1 单个用户的设定会不会影响其他用户？

**跨组织：不会串。** VIP `xingwang`（org 7）与普通 `gaoxiao`（org 8）现网对打证实：

| 设定 | 存储位置 | 写入谁 | 谁读取 | 跨组织会不会串 |
|---|---|---|---|---|
| **碰撞计算常量**（HBR 模式/半径、accepted Pc、脱靶、筛查距离、协方差模式、传播器、时间窗、步长、Pc 方法） | 表 `ca_org_defaults`，**主键 `org_id`** | 本组织 `org_admin`（或超管）`PUT /cgi/ca/defaults` | 同组织：设置页、交会详情重算（`getCaDefaults(auth.org.id)`） | **不串**。xingwang 把 `hbr_m` 改成 77.7 后 gaoxiao 仍为 `defaults=null`；反向同理 |
| **目标档案尺寸**（`mass_kg` / `cross_section_m2` / `propulsion`）及档案阈值（`accepted_pc` / `accepted_miss_km`） | 表 `objects`，**每行带 `org_id`**（同 NORAD 各组织各一行） | 认领时可写入；**后续 PATCH 仅业主认领 + VIP active** | 仅本组织 `GET /cgi/objects`；跨组织直访 ID → 403 | **不串**。同 NORAD 关注：org7 mass=111.1、org8 mass=222.2 互不可见；跨 org GET/PATCH →「无权查看/修改其他组织的目标」 |
| **筛查任务参数**（`windowH` / `missMaxKm` / `hbrM`…） | `screening_jobs.params_json` + 列，带 `org_id` | 发起任务的本组织账号（请求体；**服务端不自动读** `ca_org_defaults`） | 本组织任务列表/worker | **不串**（任务按 org 隔离） |
| **Pc 重算 run** | `conjunction_pc_runs.org_id` | 本组织重算 | 本组织 run 历史 | **不串** |
| **态势 3D 模型「看起来多大」** | 前端型号几何 + 固定缩放（`catalogCloudThree` / 交会 `eventCloudThree`） | 无用户可写的服务端尺寸字段 | 全站同一套前端逻辑 | **与用户档案无关**；改 `mass_kg` **不会**改变他人或自己的 3D 观感 |
| **浏览器 token** | `localStorage['osp-token']` | 本机登录 | 仅本浏览器 | **不影响**其他用户服务端数据 |

**同组织内：会共享（设计如此，不是跨租户泄漏）。**  
`ca_org_defaults` 是**组织一行**，不是用户一行。任一 `org_admin` 保存后，同组织其他人打开设置页 / 交会重算都会读到新默认值。当前测试账号每组织仅 1 名成员，无法双人同 org 实测，但代码路径明确。

**共享编目 NORAD 记录不会被用户尺寸写穿。**  
`sat_tle` 等系统池表**没有**用户可写的 mass/RCS/半径字段；档案尺寸只落在 `objects`。未发现无 org 条件的 `UPDATE` 把尺寸写进全局编目，也未发现进程内可变的全局 HBR 单例被请求改写。

**重要产品缺口（不算「串租户」，但要写进本册）：**

1. 档案里的 `mass_kg` / `cross_section_m2` **目前不进入**筛查 HBR、也不进入 Pc 重算、也不驱动 3D 缩放；计算侧 HBR 来自 **CA 默认 / 请求体**（缺省 15 m）。  
2. **筛查页**表单 `hbrM` 本地写死初始 15，**不会**自动预填组织 `ca_org_defaults`（与设置页/重算不一致）。

### 0.4 给 TRAE：R2-16–R2-20 怎么读（没有外部原文）

本册后半段补的是**专业操作员仪表盘**里常见的分析工作流，不是新的碰撞概率公式，也不是新的数据采购。你**不会**收到、也**不必**检索任何外部厂商幻灯或产品单页。下面五条写进实现和文案，避免误解：

1. **只依据本文。** 每个 Story 已写清：操作员看见什么、用哪套已有数据算、点哪里跳转、验收什么、哪些话不能写。  
2. **不要在产品 UI、导出报告、`docs/更新说明-*.md` 里出现第三方商业 SSA 平台/套件/商品名。** 功能名只用本平台自己的中文（或已有 i18n key）：相对运动、操作事件流、风险演变、机动后再筛查、目标档案。  
3. **不要对接任何第三方商业编目或雷达 API**，不要为系统账号增加付费拉数。数据源仅限：Space-Track TLE/CDM（客户自备凭据 + 现有封顶系统池）、客户上传的星历/CDM、本平台筛查与 Pc 重算结果。  
4. **几何与概率必须标明数据来源。** 例如「由 TLE（SGP4）传播」「由客户星历插值」「报文来源：Space-Track / 客户上传 / 本平台筛查」。禁止写或暗示：实时雷达定轨、亚 15 米状态精度、筛查后 5 分钟内出官方 CDM、TCA 前每天自动更新 5–10 次、独立发现发射 48 小时内目标等——这些都不是本平台现有数据能支撑的承诺。  
5. **「AI」不是本册的智能分析引擎。** `/ai` 只是现成路由。R2-17 用**规则**聚合已经存在的交会/机动/筛查事件；不要训练模型，不要输出「检测到对方意图/异常行为模式」这类无法从 TLE/CDM 证实的句子。

坐标系（R2-16 必读，避免和库内符号对不上）：

- 相对运动用主星（object A）的 **RTN / RIC / UVW** 同一套基。本仓库已有 `uvwBasis(r, v)`（`api/src/screen/frames.ts` 与 `web/src/views/situation/ephem/frames.ts`）：行向量 `[U, V, W]` = **径向 R**（沿主星位置，远离地球为正）、**迹向 I**（沿轨道前进，大致沿速度在垂直于 R 的投影）、**法向 C**（轨道面法向，`R × I`）。  
- 筛查结果里已有 TCA **单点** `miss_r_km` / `miss_t_km` / `miss_n_km`（即该时刻的 R/I/C 分量）。R2-16 要的是 TCA **附近一条时间序列**，不是再发明另一套轴。  
- 相对位置：`d = r_B − r_A`（与传播所用同一惯性系），再投到该时刻主星的 UVW 基上，得到 `(dR, dI, dC)`；总距离 `√(dR²+dI²+dC²)`。
